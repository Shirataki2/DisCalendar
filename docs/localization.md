# 表示言語 (#240)

日本語・英語対応を次の3段階に分けます。親 #240 は全段階の完了まで開いたままにします。

| 段階 | Issue | 対象 |
| --- | --- | --- |
| 1 | #314 | Web の言語基盤、ログイン、サーバー一覧、単独・横断カレンダー、予定操作、フォーム内の繰り返し・通知・添付・共有 |
| 2 | #315 | 設定・公開共有ページ・日程調整・ICS 取り込み・外部連携・MCP の認証案内・チュートリアル・LP・残りの利用者向け Web 案内 |
| 3 | #316 | Bot のコマンド説明・返信・エラー、個人プッシュ通知、サーバー向け通知・まとめ投稿・連携投稿 |

## Web の表示方針 (第1・第2段階)

- 初回は `navigator.language` が英語なら英語、それ以外は日本語。明示的な選択は `discalendar-language` に保存します。壊れた保存値・未対応言語は日本語です。
- `LanguageProvider` を公開ページとダッシュボードで共有します。サーバーと hydration 直後は日本語で揃え、ブラウザで選択を反映して `html.lang` も変更します。
- 言語変更は URL・認証・Query キャッシュ・予定の入力状態を作り直しません。ブラウザ保存が使えなくても同じタブでは切り替えられます。アカウント同期は #178 で扱います。
- `web/src/lib/i18n/messages.ts` は日本語の案内文をキーに持つ英訳辞書です。未定義の英訳は日本語原文にフォールバックします。変数は `{name}` のようなプレースホルダーを使い、利用者の入力を辞書キーにしません。
- 未翻訳の本文・ダイアログは `lang="ja"` を明示し、日本語として読み上げます。エラーは翻訳前の状態を保持し、言語変更後も表示を追従させます。API の既存の検証詳細も同じ辞書で翻訳し、レスポンス形式は変えません。
- クライアントの案内は `useLanguage().t`、Server Component の本文は `Message` を使います。検証ルールは共通のまま `LocalizedFieldError` で案内だけ翻訳します。
- 日時の言語別表示は JST の壁時計を保ちます。FullCalendar の言語と英語の書式を変え、週の開始曜日・保存日時・終日の日付・通知時刻は変えません。祝日は日本の祝日のままです。
- 利用規約・プライバシーポリシー・過去の更新履歴の全文翻訳、管理コンソール・開発ドキュメントの翻訳は対象外です。

## 第2段階の対象とフォールバック

- 個人・サーバー・プッシュ通知の設定、日程調整、ICS 取り込み、外部カレンダー、Webhook、MCP 認証と接続管理、公開共有、チュートリアル、LP、支援・エラー画面を同じ辞書で翻訳します。
- 使い方は日本語 `web/src/content/docs/*.mdx` と英語 `web/src/content/docs/en/*.mdx` を同じ URL で切り替えます。本文はサーバーで描画し、選択した側だけを表示・読み上げします。両言語を一緒に更新してください。
- 件数は単数・複数と桁区切り、日時は選択言語に合わせます。予定の naive 日時は JST の壁時計のまま、取得日時・MCP 接続日時などの絶対時刻は JST に固定して表示します。
- API 例外は翻訳前の状態で保持し、言語変更後もエラー表示を追従させます。サーバー名・端末名・ロール名・予定内容は辞書キーにしません。
- 公開共有の SNS メタデータ・OGP と、Bot の通知見本の本文は日本語です。ブラウザの言語設定はクローラーや Bot に送らず、通知本文・投稿は第3段階で扱います。通知見本には `lang="ja"` を明示します。
- 規約類・過去の更新履歴は日本語の本文を維持します。掲載スクリーンショットは日本語の実画面を `pnpm shot` で更新し、英語の代替テキストでその旨を案内します。

## 第3段階の通知方針

Bot の個人返信は Discord の利用者言語、チャンネルへの通知・まとめ・日程調整投稿はサーバー言語を基準にします。
サーバー言語は既存の `guilds.locale` と、管理権限で変更できる Web 設定・API を利用します。
個人プッシュ通知は購読者の Web 言語を購読時に保存し、変更時にも更新します。
API の投稿もこの個人／サーバーの区分に揃えます。未対応の言語は日本語です。

## 検証

純粋な解決・フォールバック・変数展開・日時と通知の表示は Vitest、ブラウザ保存・初期選択・別タブ・保存不可・主要な予定操作と 390px / PC は `web/e2e/language.spec.ts` で検証します。
第2段階は `web/e2e/language-remaining.spec.ts` でも設定の入力保持、公開ページと全ガイド、ICS・共有・日程調整、390px / PC を検証します。
既存の日本語 E2E と掲載スクリーンショットの再生成も行います。Bot と実 Discord の確認は第3段階で扱います。
