# 更新履歴の追加

利用者に見える変更は、機能PRでこのディレクトリに `<Issue番号>-<短い名前>.md` を追加します。
例: `249-unsaved-event.md`。同じIssueで複数のPRを出す場合も名前を分け、他のPRのファイルは編集しません。
共有の一覧ファイルへの登録は不要です。`web/src/content/changelog.mdx` には直接追記しません。

```markdown
### 入力途中の予定を誤って閉じることを防ぐようにしました

#### Web (ブラウザ)

- 未保存の変更があるときは、予定の編集画面を閉じる前に確認します。
```

- 最初の行は `### タイトル`。日付・バージョンや `#` / `##` 見出しは書きません。
- 内容は `#### Web (ブラウザ)` / `#### Bot (Discord)` / `#### API (サービス基盤)` に分け、該当する部分だけ箇条書きにします。
- 利用者に伝わる言葉で、何ができるようになったかを書きます。技術的な変更や内部変更だけなら不要です。
- 通常のMarkdownで書きます。MDXへ取り込むため、記号の `<` や `{` などはコード表記で囲みます。
- このREADMEは取り込み対象外です。

## 確認・リリース

`.github/scripts/release-notes.sh` で未リリース分を確認できます。
ファイル名のASCII昇順で結合し、移行前に `changelog.mdx` へ追記された未リリース記事があれば、その後に続けます。
並び順はマージ順ではありません。

正式版の `bump-version.sh` が個別ファイルを `changelog.mdx` へ集約し、日付・バージョン見出しを付け、取り込んだファイルを削除します。
リリース準備PRにはこの削除も含めてください。プレリリースでは集約・削除せず、リリースノートに直接反映します。
個別ファイルの内容は、正式版への集約前にはWebの更新履歴ページに表示されません。

移行時点で開いているPRは、`changelog.mdx` への追記を個別ファイルへ移してください。
すでにmainへ入っている未リリース記事は移す必要がありません。
